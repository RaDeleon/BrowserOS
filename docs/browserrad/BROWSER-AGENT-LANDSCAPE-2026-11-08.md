# Browser-agent landscape — 8 November 2026

## Scope and selection

This is a curated set of ten prominent, relevant products, **not** a measured popularity ranking. It spans a personal AI browser, open-source agent drivers, and hosted browser infrastructure. Vendor performance figures are claims about their own workloads, not BrowserRAD benchmarks. Mechanisms below come from public code or vendor documentation; private implementation details remain unknown.

BrowserRAD stays browser-only. **AgentRAD** is a working name for the separate browser-plus-desktop product, subject to a proper name and trademark check before publication.

## Implementation decisions

1. **Implemented in this branch:** \`snapshot(mode="compact")\` and \`page.snapshot({mode:"compact"})\`. The filter keeps actionable refs, headings, status/alert/log regions and their ancestors. Empty status and alert names are filled from their accessible text children so a “Saved” or error message survives. The full capture still owns the ref map; the default full mode is unchanged as an option. Tests cover MCP arguments, run-tool parsing and core rendering.
2. **Next candidate:** a bounded network-error view, scoped by page and recent time, that reports method, sanitized URL path, HTTP status, resource type and failure reason. Do not expose request/response bodies or authorization headers by default. Build only after identifying a real failure in RAD logs that this would diagnose.
3. **Later candidate:** opt-in saved read workflows, with origin binding, parameter redaction, response-shape drift detection and current-page checks. Any write must have explicit approval and no automatic resend after an unknown outcome. Compare first run and learned repeat separately.
4. **AgentRAD candidate:** handoff between browser and desktop with a visible pause/resume control and preserved task state. This belongs in the separate product, not the browser-only RAD branch.

## Could REA reveal closed-source implementations?

[REA](https://github.com/morluto/rea) advertises local inspection of desktop bundles, JavaScript/Electron modules, browser network behavior and native binaries. Its [documented outputs](https://github.com/morluto/rea#what-you-can-analyze) can support a narrow question, such as whether an installed Electron app uses an extension, what IPC boundary it exposes, or which public requests a feature makes. Native pseudocode requires a supported disassembler. Static inspection does not prove server-side behavior, model prompts, training data, or proprietary cloud architecture; runtime results depend on the observed build and session. REA was **reviewed, not installed or run** for this report. Public docs and source are sufficient for the first design pass. If a concrete unknown remains, inspect only a locally held application that we are authorized to examine, record the exact version and evidence, and respect the target's terms and third-party licenses.

## Measurement before adoption

Compare RAD with the feature disabled/enabled and Neo directly on the same task, model, browser state and postcondition. Preserve failed attempts. Measure completion, elapsed time, client-reported main-agent tokens, provider/vision use and total cost separately. A smaller snapshot or successful unit test is not an end-to-end savings claim.
